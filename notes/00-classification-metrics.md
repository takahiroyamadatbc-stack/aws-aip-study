# 分類モデルの評価指標（混同行列・正解率・適合率・再現率）

二値分類モデルの性能評価で使う基本指標。何度も忘れる原因は「Precisionの分母」と「Recallの分母」がどちらも似た形（TP+何か）をしていて混同しやすい点にあるので、**分母が「予測基準」か「実際（正解）基準」か**で覚えるのがポイント。[[50-model-evaluation]]のQ&A評価（F1スコア）や分類タスクの正確性（Accuracy）はここで定義する指標がベースになっている。

## 混同行列（Confusion Matrix）

「実際のクラス（正解ラベル）」と「モデルの予測クラス」の組み合わせを2×2で整理した表。TP/TN/FP/FNの4象限がすべての指標の土台になる。

| | 予測: Positive | 予測: Negative |
|---|---|---|
| **実際: Positive** | TP（True Positive）<br>陽性を正しく陽性と予測 | FN（False Negative）<br>陽性を誤って陰性と予測（**見逃し**） |
| **実際: Negative** | FP（False Positive）<br>陰性を誤って陽性と予測（**誤検知**） | TN（True Negative）<br>陰性を正しく陰性と予測 |

- 行＝実際の正解、列＝モデルの予測、と覚える（表計算的にも「実際×予測」のクロス集計）
- **FN（見逃し）とFP（誤検知）はどちらが問題かはユースケース依存**。例: 不正検知や病気診断はFN（見逃し）を減らしたい＝Recall重視。スパムフィルタや誤警報を嫌う監視系はFP（誤検知）を減らしたい＝Precision重視

## 3つの式

| 指標 | 式 | 意味（分母は何を基準にしているか） |
|---|---|---|
| **正解率（Accuracy）** | $\dfrac{TP + TN}{TP + TN + FP + FN}$ | 全予測件数のうち正解した割合。分母＝**全データ** |
| **適合率（Precision）** | $\dfrac{TP}{TP + FP}$ | 「陽性と予測した」もののうち実際に陽性だった割合。分母＝**予測がPositiveだったもの**（TP+FP） |
| **再現率（Recall）**<br>（Sensitivity, TPR） | $\dfrac{TP}{TP + FN}$ | 「実際に陽性だった」もののうち正しく検出できた割合。分母＝**実際にPositiveだったもの**（TP+FN） |
| **F1スコア** | $\dfrac{2 \times Precision \times Recall}{Precision + Recall}$ | PrecisionとRecallの調和平均。両者のバランスを1つの数値で見たいときに使う |

覚え方の軸:
- **Precision＝「予測」基準**（分母にFPが入る＝予測をPositiveと言い切った中でのミス）
- **Recall＝「正解」基準**（分母にFNが入る＝本当はPositiveだったのに見逃した数）
- 頭文字で迷ったら「Precision＝的中率（撃った弾のうち当たった割合）」「Recall＝網羅率（当てるべき的のうち当てられた割合）」とイメージすると分母を取り違えにくい

## 試験の勘所

- **不均衡データ（クラスの偏りが大きいデータ）ではAccuracyだけでは判断できない**。例: 陽性が全体の1%しかないデータで「常にNegativeと予測するモデル」でもAccuracyは99%になり得るが、Recallは0%（陽性を一つも検出できていない）。AIP-C01では「Accuracyが高い＝良いモデル」という誤答選択肢が典型的な引っ掛けとして出やすい
- PrecisionとRecallはトレードオフの関係になりやすい（閾値を下げてPositive判定を増やすとRecallは上がるがPrecisionは下がる、逆も同様）。両方を天秤にかけたい場合にF1スコアを使う、という位置づけを押さえる
- [[50-model-evaluation]]のBedrock自動評価でのQ&AタスクのAccuracy指標は内部的にF1スコア（この表のF1と同じ定義）を使っている。「正確性」という名前でも中身は分類の一致率ではなくF1である点に注意
