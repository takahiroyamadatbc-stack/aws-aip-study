# bad-questions

問題集を解いていて、正誤とは別に「解説・想定解答の説明が不十分／根拠が薄い／実際の仕様と食い違う」と判断した問題を集めるフォルダ。あとで問題作成元へのフィードバックとして投げる材料にする。

`labs/` や `notes/` とは目的が異なる（学習ログではなく、問題そのものへの指摘）ため、リポジトリ直下に独立して置く。

## 対象にする問題の基準

- 選んだ答え（正解/不正解を問わない）自体に異論はないが、**解説の論拠が弱い・こじつけ気味・実際のAWSサービス仕様と食い違う**もの
- 複数の選択肢が同程度に正解になり得る、または想定解答の根拠が公式ドキュメントで裏付けられないもの
- 選択肢自体の**情報量が不十分、または要件判定に寄与しない蛇足的な記述が多い**もの（正誤判定の決め手にならないサービス名の羅列や、要件と無関係な修飾が選択肢の長さを水増ししているだけのケースなど）

単なる「知らなかった／理解不足だった」という誤答は対象外（そちらは `notes/` へ知識整理する）。

## ファイル命名規則

`SET-NN-service-name.md`

- `SET`: 問題集を識別するプレフィックス。複数の問題集を横断して`NN`（問題番号）が重複するため、問題集ごとに割り当てる
  - `mar`: 作者名"mar"の問題集（AIP-C01、既存75問）
  - `syo`: 作者名"syo"の問題集（AIP-C01、75問＋75問＋10問の3パート構成）。パートが複数あるため`syo1` / `syo2` / `syo3`のように内部で更に分ける
- `NN`: 問題の番号を2桁ゼロ埋め（各問題集内での番号。問題集をまたいで通し番号にはしない）
- `service-name`: 論点となっている主要なAWSサービス名（kebab-case、複数サービスが絡む場合は最も中心的なもの1つ）

例: `mar-09-bedrock-prompt-management.md`、`syo1-03-sagemaker-model-monitor.md`

新しい問題集に着手する際は、その問題集の作者名・パート構成に応じて上記の対応表にプレフィックスを追記すること。

## ファイルの記載内容

各ファイルには以下を含める。

1. **問題文・選択肢・想定解答**（原文のまま引用）
2. **論点**: どの解説記述に対して疑問を持ったか
3. **検証結果**: 公式ドキュメント等で確認した事実と、それに基づく指摘（出典リンク付き）
4. **結論**: 作者に伝えたい指摘の要約
